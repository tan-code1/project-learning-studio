# Obsidian 落地与目录整理

## 先确定库与现有状态

找到实际 Obsidian 库根及其配置目录，不能仅根据用户给出的父文件夹猜测。检查目标子目录、现有入口、主题、插件和自动目录模板设置。仅操作用户置于范围内的课程。已有内容先读再改；需要批量迁移时记录备份和前后路径。

观察到大量“未命名”目录时，逐个确认是否只有自动目录模板、空查询表和自动链接区。名称相同不表示内容可丢弃。有个人正文、附件或无法判定内容的目录应保留。确认无学习正文的模板可移动到库外的可恢复备份，记录原路径。

若自动目录笔记插件确实在为这门课制造模板，可对课程子目录增加排除项并保留其他设置，确认变更已生效。不要因一次局部问题全局关闭用户的目录功能。

## 简洁的日常入口

优先在新课程建立时使用中文名称：
- 开始学习：第一天怎么做和所有入口；
- 学习进度面板：已完成、进行中和接续点；
- 每日课程：逐课讲义；
- 复习练习：复习和独立挑战；
- 资料说明：运行、答案、数据、结果与来源的索引。

工程目录可保留约定名称，如 notebooks、data、scripts、results、references、reports。先解释用途，并在文件浏览器中按需隐藏，而不是强行迁移会影响程序的目录。隐藏是界面简化，不是删除、访问控制或搜索排除；相关链接应仍可打开。

如使用 CSS 简化，选择器必须限定实际库内课程路径和文件浏览器，不影响整个库。提供关闭片段以恢复完整列表的方法。保持现有主题，使用其颜色和字体变量。必须在实际 Obsidian 中核对目录和入口，而不是仅验证 CSS 文本。

资料说明需要回答：什么时候打开哪份文件、Notebook 在哪里、后台文件做什么、如何显示全部。

## 链接与改名

以 course.json 的稳定 ID、路径、顺序为共同来源。所有讲义与导航使用可移植相对链接或已验证的库内链接。

重命名每日课程等目录时：
1. 建立旧路径到新路径映射与可恢复备份；
2. 迁移讲义、课程清单、Notebook Markdown 中的引用、导出链接和进度面板路径；
3. 保持课程 ID 与进度文件不变；
4. 检查旧文件夹同名目录笔记是否也需要改名；
5. 验证本地链接、清单条目和真实跳转，处理仍指向旧路径的标签页。

不要把自动生成的 Waypoint 区域与人工导航混写；需要纯手工导航时移除对应自动标记，并留旧版本备份。更改文件系统后注意 Obsidian 正在运行的插件可能覆盖旧配置，可通过正常退出/重新加载后再次核对。

## 交付视角

先把课程首页或进度面板打开给用户。入口数量控制在容易理解的范围，详细安装、许可、验证等资料通过导航访问。需要解释“什么被移动、什么只被隐藏、怎么恢复”，不只说目录已清理。
