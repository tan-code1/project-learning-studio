# 学习进度面板

## 使用同一份课程清单

使用 assets/course.example.json 的字段作为起点，按实际课程填充。清单至少包括 schemaVersion、courseId、title、技能目录，以及课时的稳定 id、kind、order、group、title、lecture、notebook 和 skills。路径相对课程根；notebook 可为 null。分组可按周、阶段或章节命名，不固定为四周。

推荐让一个安装的插件支持选择课程清单，或为独立课程生成带清单的打包插件。复用现有插件时保留已有课程和记录。课程总数、分组进度、核心课/复习计数、技能覆盖均由清单计算。

## 状态与接续规则

进度与清单分开存储，按 courseId 与 item.id 定位；标题和目录改名不重置进度。版本化保存结构，例如 schemaVersion、courseId、items、lastActiveId、updatedAt、events。每项记录检查点、开始/完成时间和接续笔记。

可采用三个手动检查点：
- 理解讲解：能用自己的话解释关键概念；
- 动手练习：本人运行代码或完成练习；
- 完成自检：能解释结果与局限。

三项全选计为完成，可撤销；部分确认或主动开始计为进行中。只浏览文件不计学习活动。接续推荐优先最近正在学习且未完成的课；没有进行中项时按清单顺序找最早未完成项；全部完成时显示复习与导出入口。

保存接续笔记时显示明确成功/失败状态。未保存草稿不应因勾选、筛选或另一个面板刷新而丢失。下一次显示接续笔记，不能只保存一个课名。

## 界面

完整面板：总进度、当前接续点、课程路线、状态筛选、当前课检查点、接续笔记、已学技能相关课程数、近期记录、导出。

侧栏：当前课的简洁检查点和笔记，跟随当前打开的讲义。侧栏初始化也要读取当前文件；不要只依赖后续 file-open 事件。窄侧栏不应重复完整课程网格。

Markdown 嵌入面板可以作为额外入口，阅读视图中确认可用。使用语义化按钮、文本标签、键盘焦点和主题变量；检查窄布局与深浅色适配。技能覆盖不标为熟练度或职业资质评分。

## Obsidian 实现要点

实现前核对实际版本的官方开发文档。常用接口包括 Plugin、ItemView、MarkdownRenderChild、loadData/saveData、命令、工作区事件与本地 vault 文件接口；按当前 API 和应用版本选择，不能把这里当固定 API 合约。

交付可独立加载的 main.js 和 manifest.json，样式可单独 styles.css。将相对导入的本地模块打包进 main.js，保留 obsidian 作为外部宿主依赖。Node 的 require('./core') 成功不能证明 Obsidian 插件宿主也能解析它。

运行时读取外置清单可通过目标库接口，或构建时嵌入；安装和更新时不要复制模板 data.json 覆盖用户记录。统一序列化写入，避免快速点击丢失更新；保存失败保留之前状态并告知用户。遇到未知新版数据格式时保留原文件，不用空状态覆盖。合理限制历史记录长度，并提供可读 Markdown 与 JSON 快照导出。

显示接续笔记用文本节点，避免把用户笔记当 HTML 注入。仅有本地功能时无需网络请求。已有同步软件可能同步进度目录；不能宣称“绝不离开本机”，也不能默认提供了多设备冲突合并能力。

## 有意义的验证

使用隔离样例，而不是给用户真实课程打测试完成标记：
- 全新课程为零，访问文件不完成；
- 部分勾选、完成、撤销与下一课推荐正确；
- 改名后稳定 ID 的进度仍能恢复；
- 保存和重新加载能恢复检查点与接续笔记；
- 连续保存不丢记录，保存失败不假报成功；
- 筛选、侧栏跟随、导出链接与清单一致；
- 课时数量或分组变化后统计仍正确。

在实际目标 Obsidian 内确认插件启用、界面可见、讲义跳转和重载后的记录。不要以测试宿主中的 DOM 渲染代替真实宿主验证。若借用户环境测试写入，先备份并精确恢复本次测试造成的数据，保留同期用户修改。
